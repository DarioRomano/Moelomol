# 2026-10-09: Fullscreen shortcuts (Q6d)

## What was done

The lead accepted the Q6 recommendations. This PR implements Q6d's
shortcuts, since the game starts fullscreen and had no way out:
- Actions `toggle_fullscreen` (Alt+Enter and Alt+keypad Enter) and
  `toggle_fullscreen_macos` (Ctrl+Cmd+F) in `project.godot`.
- Autoload `WindowControls` toggles between fullscreen and windowed; each
  platform answers only its own shortcut; key repeat is ignored.
- 7 tests; playtest checklist item 6b.

The options-menu setting for fullscreen (the other half of Q6d) comes with
the first menu.

## What broke, and how it was found

- **The engine writes new key events with `"device":16`.** The action entries
  were generated by the engine (`ProjectSettings.save()`) to get the format
  right; editor-made actions use `-1` (any device). Probed: a real keyboard
  event has device 16, and an action with device -1 matches it. `-1` used.
- **My throwaway generator script failed to parse:** the project's
  untyped-declaration rule applies to every script run in the project.

## Verified

- With the engine: Alt+Enter matches the action, plain Enter does not,
  Alt+Shift+Enter does (harmless).
- The exported Linux build smoke-runs with the autoload, no errors.

## Test mutations (each confirmed to fail, then reverted)

Exclusive fullscreen not treated as fullscreen; macOS answering Alt+Enter;
key repeat allowed; handler not switching; autoload removed; keypad Enter
unbound.

## Not verified

The real window switching on Windows, macOS and Linux (no window manager
here), and whether macOS also handles Ctrl+Cmd+F itself: playtest item 6b.
