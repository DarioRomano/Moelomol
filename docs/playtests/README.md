# Playtests

Some things cannot be verified headlessly: how the game feels, input
responsiveness, controller behaviour, the audio mix, and performance on real
machines. The engineer does not claim them. Instead, each such item goes on a
checklist here for the project lead to run.

## Format

One file per checklist: `YYYY-MM-DD-short-topic.md`. Each contains:

1. **Build:** which commit or PR, and how to get or run it.
2. **Setup:** machine, OS, screen size, input device, speakers or headphones.
3. **Checks:** numbered, each a concrete action and what to look or listen for.
   Each check has a blank result line: `Result: pass / fail / notes`.
4. **Report back:** the lead fills in results; the engineer turns failures into
   issues or progress notes.
